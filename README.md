# ru_text

ロシア語能力検定試験3級→2級(CEFR B1〜B2相当)の間にある語彙ギャップを埋めるための
教科書プロジェクトの、語彙選定パイプラインを管理するリポジトリ。

## 現在の方針

1. 「日常生活・時事・娯楽・一般教養」に広く分散させたトピック集(`data/topics/`)を元に、
   一般の成人読者向けの自然なロシア語文章を大量に生成する。専門家向けの専門用語や
   文学的・古風な表現を意図的に多用しない一方、学習者向けに語彙や文法を不自然に
   単純化しない。
2. 生成した文章から `scripts/extract_vocabulary_stanza.py` で語彙を抽出・レンマ化し、
   出現頻度と形態情報を集計する。
3. この生成・抽出工程の目的は、CEFRレベルを機械的に判定することではなく、人力では
   漏れなく列挙しにくい語彙候補を大量の自然な文脈から発見することである。頻度は
   候補の発見・整理に利用する。
4. 一般向け文章の中で自然に必要となって現れた語は、C1/C2相当と思われる語であっても
   自動的には除外しない。難易度ラベルよりも、その文脈で登場する意味があることを重視する。
5. 最終的に教材へ採用する語彙は、人間が生成元の文脈も確認したうえで決定する。

## 文章生成時の制約

文章生成の目的は、その文章自体を完成した教材として使うことではなく、自然な文脈から
語彙候補を広く回収することである。以下を生成時の共通ルールとする。

- 語彙や文法を「学習者向け」に意図的に単純化しない。レジスターは文体の指定であり、
  CEFR上の上限ではない。一方、語彙数を稼ぐためだけに不自然な難語を詰め込まない。
- 数詞の格変化、形動詞、副動詞など特定の文法現象を出したい場合も、その文法を解説する
  文章にはしない。年齢・買い物・移動・複数の動作の描写など、その形が自然に必要になる
  場面を作って実際に使用する。
- 法律・医療・科学・時事など事実性が重要な話題では、地域や時点で変わる制度・期限・
  数値・因果関係を一般則として作らない。必要な前提が与えられていない場合は安定した
  一般論に留め、不確実な内容は断定しない。企業・組織・個人の意図や動機についても、
  根拠なく「意図的に〜している」と事実として決めつけない。
- 法律・医療・科学・歴史・地理・経済・時事など、文章の中心が事実説明になるトピックは
  可能な限り source-first で生成する。先に実在する信頼できる情報源を確認し、その範囲で
  内容を書く。法令本文、公的機関・国際機関、査読論文、大学・博物館・学術出版社などを
  優先し、出典を確認できない具体的事実は作らない。信頼できる情報を確認できない場合は
  固有名詞・数値・因果を減らして安定した一般論にする。なお、目的は自然な語彙コーパスを
  作ることであり、出典URLや引用を本文へ不自然に埋め込む必要はない。
- 報道文体でも、実在のニュースに見える架空の固有地名・行政機関・発表主体・施設規模・
  統計値を組み合わせて「事実」を作らない。実在事項を確認していない場合は、
  「ある都市の一地区」のような一般的な設定にし、具体的な行政発表や数値を捏造しない。
- 社会科学・心理学・言語学・文化論では、相関や一部の研究で見られる傾向を普遍的な
  因果関係や集団の本質として書かない。個人差・地域差が大きい話題や研究上の議論が
  続いている話題は、その不確実性が分かる表現にする。
- 歴史・文化を扱う際は、現代国家の国境や国民概念を過去へそのまま投影しない。
  複数の国・民族が継承する歴史や広い地域で共有される文化を、根拠なく一国だけの
  直線的・排他的な起源として説明しない。時代に合った地名・政治体の名称を優先する。
- 「専門家によれば」「研究によれば」などの権威付けを根拠のない定型句として使わない。
  ロシア語の本文でも `мнения экспертов расходятся` や `исследователи считают`
  のように主体を置くだけで根拠らしく見せる表現は同様に避ける。特定の出典を確認して
  いない場合は、`прогнозы расходятся` のように主張そのものを一般的・条件付きに書く。
- 年齢、価格、時刻、点数など架空の具体的場面を成立させるための数字は積極的に使ってよい。
  一方、現実世界の統計値や法律上の期限を、語彙を増やすためだけに創作しない。金融・健康・
  安全などの実用助言でも、「収入の3分の1まで」のような丸い数値を普遍的な推奨基準として
  作らない。基準が地域・制度・個人条件で変わる場合は、その変数を説明する。
- 多数の文章で同じ論述テンプレートを繰り返さない。「с одной стороны ... с другой стороны」、
  「эксперты отмечают」、「тем не менее」などは必要な場合だけ使い、導入・接続・結論の
  組み立てをトピックに応じて変える。これは生成コーパスの語彙・構文の偏りを減らすためである。
- 1トピック100〜150語程度を目安に、単独で自然に読めるロシア語文章にする。自然に完結するなら多少短くてもよく、語数を合わせるためだけの水増しはしない。

## 語彙と文法の扱い

このパイプラインで統計的に大規模収集する主対象は単語である。イディオム、格支配、
相関接続表現などの文法・定型表現は、既存教材、信頼できる資料、生成済み文章などを
参照して別途整理する。これらは現実的に人間が収集・確認できる規模であり、単語と同じ
仕組みに統合すること自体を目的にはしない。

ただし、レンマ化だけでは消えてしまう形態上の違いは明示的に保存する。特に
деепричастие(副動詞)・причастие(形動詞)はB1〜B2付近の学習で重要であるため、
`verb_form` ごとに別行として集計し、統計上も目立つようにする。一方、名詞・
形容詞・数詞などの格変化は同じlemmaを格ごとに別単語のように分割しない。
同じ行の `case_counts` に格別の出現回数をまとめ、語彙リストとしての見通しと
格変化の統計を両立させる。格支配などを詳しく確認したい場合は、保存してある
生成元文章に戻って実際の文脈を参照できる。

## ディレクトリ構成

- `data/topics/` — 文章生成用のトピック集
- `data/generated_texts/passages/` — 生成したロシア語文章。1トピック1ファイル
  (例: `0001.txt`)のプレーンテキストとして保存する。
- `data/generated_texts/manifest.csv` — 各`passages/*.txt`がどのカテゴリ・
  トピック・想定レジスターから生成されたかを記録するメタ情報
  (列: `id,category,topic,register,filename`)。抽出スクリプトはこのファイルを
  読まない(後述)。
- `scripts/` — 語彙抽出用のスクリプト
- `extracted_vocabulary_stanza.csv` — 全 `passages/*.txt` から Stanza で再生成する語彙集計。\n  GitHub Actions は差分追記ではなく毎回全パッセージを再処理してこのファイルを完全上書きする。\n  そのため本文の追加・修正・削除があっても、過去分の二重計上や古い集計の残留を避けられる。\n- `vocabulary_classification.csv` — 語彙整理用の粗い分類表。列は `lemma,upos,lexical_class` の3つだけで、\n  `lexical_class` は `everyday`(日常語彙) / `general`(一般語彙) / `specialized`(専門語彙) の3値。\n  初回は出現トピックの種類と一般ロシア語での使用頻度を補助情報として自動分類するが、重要度や\n  CEFRを推定するものではない。以後のActionsでは既存ラベルを保持し、新しく抽出された語だけを\n  自動分類するため、人間が後から直した分類は上書きされない。\n
## Stanza補正レイヤー

Stanzaのロシア語解析には、未知語・命令形・格変化形・`ё`を含む語などで、
非語のlemma、語幹だけのlemma、誤ったUPOSが混じることがある。
生成CSVを直接手修正すると次回Actionsで消えるため、
`data/lemma_corrections.csv` を補正の正本とする。

- `scripts/lemma_corrections.py` がStanza出力直後に補正を適用する。
- 抽出と分類の両方が同じ補正器を通るため、`(lemma, upos)` のキーがずれない。
- 補正表は `replace` または `drop` の明示ルールだけを持つ。
- 数字だけのトークン、年、日付、Latin-onlyのブランド名・略号など、
  ロシア語語彙として扱わない非語彙トークンもこの層で除外する。
- `scripts/audit_lemmas_pymorphy.py` はpymorphy3を独立した第二意見として使い、
  新規の怪しいlemma候補を列挙する保守用ツールである。自動修正は行わない。
- 補正表の重複・連鎖置換・不正actionなどは `tests/test_lemma_corrections.py` で検査し、
  Actionsは語彙再生成の前にこのテストを実行する。

補正は「Stanzaよりpymorphy3を常に正しいとみなす」仕組みではなく、
実際に確認した誤解析だけを明示的に直す保守層である。

## 抽出結果の形式

`scripts/extract_vocabulary_stanza.py` の出力は
`lemma,upos,verb_form,case_counts,example_wordform,count` の列を持つ。
集計キーは `(lemma, upos, verb_form)` であるため、同じ動詞でも
定動詞・副動詞(`verb_form=Conv`)・形動詞(`verb_form=Part`)として出現した
回数を別々に確認できる。一方、格は集計キーに含めないので、たとえば
`новый / нового / новому` のような格変化が同じlemmaについて複数行に
分裂することはない。

`case_counts` には、その行で観測された格別の出現回数を
`Acc:4|Gen:3|Nom:8` のように保存する。これにより1単語1行に近い見通しを
保ちながら、名詞・形容詞・数詞などの格変化を統計上確認できる。
`example_wordform` にはその分類で実際に出現した語形を1つ保存する。
必要に応じて `data/generated_texts/passages/` の元ファイルと
`data/generated_texts/manifest.csv` を参照し、格支配を含む具体的な用法や
文脈、どのトピックから来た語かを確認する。

## 生成文章の置き場所と分量の目安

- 出力先: `data/generated_texts/passages/0001.txt`のような、1トピック1ファイルの
  プレーンテキスト。CSVの1列に本文を入れる形式も検討したが、カンマ・改行を含む
  自然文をCSVの1フィールドとして扱うと(csvモジュールで技術的には正しく
  クォートされるとはいえ)人間が直接編集する際にクォート規則を意識する必要が
  生じ、gitの差分も1トピックの変更が他行に影響して見えにくくなる。1トピック
  1ファイルなら常にプレーンテキストとして開け、差分も1ファイルに閉じるため
  こちらを採用する。
- 出自の記録: `data/generated_texts/manifest.csv`
  (列: `id,category,topic,register,filename`)に、どの`passages/*.txt`が
  どのカテゴリ・トピック・想定レジスターから生成されたかを記録する。
  デバッグや、特定トピックだけ生成量を増やしたい場合の絞り込みに利用する。
  抽出スクリプト(`extract_vocabulary_stanza.py`)は`passages/`配下の本文だけを
  読み、このmanifestは読まない(生成側のメタ情報と抽出処理の責務を分離する)。
- 分量の目安: 1トピックあたり100〜150語程度から始める。
  文章そのものの完成度ではなく語彙候補の発見が目的なので、まず実際に生成して
  異なりlemma数と語彙の広がりを測定し、不足していればトピック数または
  1トピックあたりの分量を増やす。先に必要量を厳密に決め打ちしない。
- `register` 列は難易度指定ではなく、文章形式・文体を選ぶための緩やかな目安である。
  たとえば「口語」は硬い書き言葉ではないという程度の指定であり、必ず会話形式に
  することを意味しない。「一般向け解説」も語彙を初級向けに制限する指示ではない。
  どのレジスターでも、不自然に語彙や文法を単純化しない自然なロシア語を優先する。

## 実行環境についての注意

`scripts/extract_vocabulary_stanza.py` は Stanza(PyTorchベース、未知語耐性が高い)を
使う。ロシア語モデルはHuggingFace経由でのみ配布されているため、HuggingFaceへの
アクセスが制限された環境では実行できない。モデルは `~/.cache/stanza/` に
キャッシュされるため、CI環境で実行する場合は `actions/cache` での永続化を推奨する。

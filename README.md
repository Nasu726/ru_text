# ru_text

ロシア語検定(ТРКИ)3級→2級の間にある語彙ギャップを埋めるための教科書プロジェクトの、
語彙選定パイプラインを管理するリポジトリ。

## 現在の方針

1. 「日常生活・時事・娯楽・一般教養」に絞ったトピック集(`data/topics/`)を元に、
   常に「啓蒙的・平易な文体」で大量の文章を生成する(専門的すぎるトピックや
   堅い文体はCEFRの想定を超える語彙を持ち込むことが分かっているため避ける)。
2. 生成した文章から `scripts/extract_vocabulary_stanza.py` で語彙を抽出・レンマ化する。
3. 抽出した各語のCEFRレベルは、Claudeの教育的判断による一次推定で割り当てる。
4. 最終的な採否はユーザー自身による手動レビュー(ブラックリスト作業)で確定する。

## ディレクトリ構成

- `data/topics/` — 文章生成用のトピック集
- `scripts/` — 語彙抽出用のスクリプト

## 抽出結果の形式

`scripts/extract_vocabulary_stanza.py` の出力は `lemma,upos,verb_form,case,
example_wordform,count` の列を持つ。lemma単位ではなく `(lemma, upos,
verb_form, case)` 単位で集計しているため、同じ動詞でも定動詞・副動詞
(деепричастие, verb_form=Conv)・形動詞(причастие, verb_form=Part)として
出現した回数を別々に確認できる。同様に名詞・数詞がどの格(case)で
出現したかも残るため、格支配や数詞の格変化がどの程度カバーされているかを
後から集計できる。

## 生成文章の置き場所と分量の目安

- 出力先: `data/generated_texts/ru_generated_texts.csv`
  (列: `category,topic,register,text`)。
  Why CSVにするのか: 1行1パッセージのプレーンテキストではなく、
  どのカテゴリ・どのトピック・どの想定レジスターから生成された文章かを
  後から追跡できるようにするため(デバッグや、特定トピックだけ生成量を
  増やしたい場合の絞り込みに使う)。
- 分量の目安: 1トピックあたり100〜150語程度から始める。
  Why この数字なのか: あくまで語彙リスト抽出が目的であり、文章としての
  完成度は求めていないため、多すぎず少なすぎない量として設定した
  暫定値。パイロット実験(900語→異なりlemma424語)からのHeaps則的な
  外挿では、322トピック×形125語≒4万語の生成でТРКИ B2までの累積目標
  (約5,100語)に届くかは楽観できないが、トピックの多様性そのものが
  素朴な外挿より語彙の伸びを押し上げると考えられるため、実際に一度
  生成してから異なりlemma数を測定し、不足していればトピックを増やすか
  1トピックあたりの分量を増やす形で調整する(先に厳密な計算をして
  分量を決め打ちしない、というYAGNI的な進め方)。
- レジスター(`register`列、例: 口語)の意味について: 「口語」は
  「硬い書き言葉ではない」という程度の緩い指定であり、実際に喋っている
  ような掛け合い口調で書くことを意味しない。300トピック全てを会話調に
  するのは不自然かつ非効率なので、平易で自然な地の文として書けば良い。
  register列はあくまで文体選択の緩やかな目安であり、厳密なフォーマット
  要件ではない。

## 実行環境についての注意

`scripts/extract_vocabulary_stanza.py` は Stanza(PyTorchベース、未知語耐性が高い)を
使う。ロシア語モデルはHuggingFace経由でのみ配布されているため、HuggingFaceへの
アクセスが制限された環境では実行できない。モデルは `~/.cache/stanza/` に
キャッシュされるため、CI環境で実行する場合は `actions/cache` での永続化を推奨する。

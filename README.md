# ru_text

ロシア語能力検定試験3級→2級(CEFR B1〜B2相当)の間にある語彙ギャップを埋めるための
教科書プロジェクトの、語彙選定パイプラインを管理するリポジトリ。

## 現在の方針

1. 「日常生活・時事・娯楽・一般教養」に広く分散させたトピック集(`data/topics/`)を元に、
   一般の成人読者向けの自然なロシア語文章を大量に生成する。専門家向けの専門用語や
   文学的・古風な表現を意図的に多用しない一方、学習者向けに語彙や文法を不自然に
   単純化しない。
2. 生成した文章から `scripts/extract_vocabulary_stanza.py` で語彙を抽出・レンマ化し、
   出現頻度と形態情報を集計する。
3. この生成・抽出工程の目的は、CEFRレベルを機械的に判定することではなく、人力では
   漏れなく列挙しにくい語彙候補を大量の自然な文脈から発見することである。頻度は
   候補の発見・整理に利用する。
4. 一般向け文章の中で自然に必要となって現れた語は、C1/C2相当と思われる語であっても
   自動的には除外しない。難易度ラベルよりも、その文脈で登場する意味があることを重視する。
5. 最終的に教材へ採用する語彙は、人間が生成元の文脈も確認したうえで決定する。

## 語彙と文法の扱い

このパイプラインで統計的に大規模収集する主対象は単語である。イディオム、格支配、
相関接続表現などの文法・定型表現は、既存教材、信頼できる資料、生成済み文章などを
参照して別途整理する。これらは現実的に人間が収集・確認できる規模であり、単語と同じ
仕組みに統合すること自体を目的にはしない。

ただし、レンマ化だけでは消えてしまう形態上の違いは明示的に保存する。特に
деепричастие(副動詞)・причастие(形動詞)はB1〜B2付近の学習で重要であるため、
`verb_form` ごとに別行として集計し、統計上も目立つようにする。一方、名詞・
形容詞・数詞などの格変化は同じlemmaを格ごとに別単語のように分割しない。
同じ行の `case_counts` に格別の出現回数をまとめ、語彙リストとしての見通しと
格変化の統計を両立させる。格支配などを詳しく確認したい場合は、保存してある
生成元文章に戻って実際の文脈を参照できる。

## ディレクトリ構成

- `data/topics/` — 文章生成用のトピック集
- `data/generated_texts/` — 生成したロシア語文章
- `scripts/` — 語彙抽出用のスクリプト

## 抽出結果の形式

`scripts/extract_vocabulary_stanza.py` の出力は
`lemma,upos,verb_form,case_counts,example_wordform,count` の列を持つ。
集計キーは `(lemma, upos, verb_form)` であるため、同じ動詞でも
定動詞・副動詞(`verb_form=Conv`)・形動詞(`verb_form=Part`)として出現した
回数を別々に確認できる。一方、格は集計キーに含めないので、たとえば
`новый / нового / новому` のような格変化が同じlemmaについて複数行に
分裂することはない。

`case_counts` には、その行で観測された格別の出現回数を
`Acc:4|Gen:3|Nom:8` のように保存する。これにより1単語1行に近い見通しを
保ちながら、名詞・形容詞・数詞などの格変化を統計上確認できる。
`example_wordform` にはその分類で実際に出現した語形を1つ保存する。
必要に応じて `data/generated_texts/ru_generated_texts.csv` の元文章を参照し、
格支配を含む具体的な用法や文脈を確認する。

## 生成文章の置き場所と分量の目安

- 出力先: `data/generated_texts/ru_generated_texts.csv`
  (列: `category,topic,register,text`)。
  CSVにすることで、どのカテゴリ・トピック・想定レジスターから生成された文章かを
  後から追跡できる。デバッグや、特定トピックだけ生成量を増やしたい場合の
  絞り込みにも利用する。
- 分量の目安: 1トピックあたり100〜150語程度から始める。
  文章そのものの完成度ではなく語彙候補の発見が目的なので、まず実際に生成して
  異なりlemma数と語彙の広がりを測定し、不足していればトピック数または
  1トピックあたりの分量を増やす。先に必要量を厳密に決め打ちしない。
- `register` 列は難易度指定ではなく、文章形式・文体を選ぶための緩やかな目安である。
  たとえば「口語」は硬い書き言葉ではないという程度の指定であり、必ず会話形式に
  することを意味しない。「一般向け解説」も語彙を初級向けに制限する指示ではない。
  どのレジスターでも、不自然に語彙や文法を単純化しない自然なロシア語を優先する。

## 実行環境についての注意

`scripts/extract_vocabulary_stanza.py` は Stanza(PyTorchベース、未知語耐性が高い)を
使う。ロシア語モデルはHuggingFace経由でのみ配布されているため、HuggingFaceへの
アクセスが制限された環境では実行できない。モデルは `~/.cache/stanza/` に
キャッシュされるため、CI環境で実行する場合は `actions/cache` での永続化を推奨する。
